SECURELINK - PROGRESS DEMO
==========================

What this is:
  A demo of what is working TODAY, using only this laptop (no phone, no
  Wireshark recording yet). It has three parts:
    PART 1 - SHOWCASE : features you can use and show on screen right now
    PART 2 - VERIFY   : look "under the hood" to prove the security is real
    PART 3 - NOT SHOWN YET : what is still left, and what it needs

How to read this file:
  - Do the steps in order.
  - "SEE:" is what should appear on screen.
  - "SAY:" is one simple sentence to tell the audience.
  - Text inside [ ] is something you click or type.

Time needed: about 25 minutes (plus 10 minutes to get ready).


=====================================================================
GET READY (10 minutes before)
=====================================================================

R1. Open PowerShell in the project folder and start the app:
        .venv\Scripts\python backend\run.py
    Leave it open. This is the "SERVER WINDOW".
    To stop the app: click this window and press Ctrl+C.

R2. Open a SECOND PowerShell window in the project folder.
    This is the "SCRIPT WINDOW". You will type commands here.

R3. Chrome: go to  https://localhost:8443  and log in as  admin
    Click [Admin] > [Users] and create these people
    (use the same password for all, e.g. Demo#2026pass):
        hr_anna  - Anna Rao  - Human Resources - role HR
        hr_bob   - Bob Mehta - Human Resources - role HR
        dev_dan  - Dan Iyer  - Engineering     - role Developer
    Do NOT create Carl yet. You will do that live.

R4. Make the demo files. In the SCRIPT WINDOW type:
        .venv\Scripts\python scripts\make_spoofed_file.py
    This creates  demo_files\invoice.pdf  (a program pretending to be a PDF).
    Also put these in the demo_files folder:
        - any PDF, renamed  hr_salaries.pdf
        - a copy of it, renamed  hr_appraisals.pdf
        - any photo, renamed  team_photo.jpg

R5. Open these windows (one browser window = one person):
        Chrome            -> admin   (already open)
        Edge              -> hr_anna (go to https://localhost:8443 and log in)
        Chrome Incognito  -> hr_bob  (press Ctrl+Shift+N in Chrome)
    Carl will use Edge InPrivate later (Ctrl+Shift+N in Edge).

R6. In Chrome AND Edge: right-click the address bar and tick
    [Always show full URLs], so the audience sees the full https:// address.

=====================================================================
PART 2 - VERIFY (prove it's really secure)
=====================================================================

--- V1. The certificate is real ---
1. Chrome: click the padlock > "Connection is secure" > "Certificate is valid".
   SEE: Issued by "SecureLink Local CA".
   SAY: "Our own company certificate authority signs the server's certificate."

--- V2. Passwords are never stored ---
1. SCRIPT WINDOW: type
        .venv\Scripts\python -c "import sqlite3;[print(r) for r in sqlite3.connect('backend/data/securelink.db').execute('select user_id,password_hash from users')]"
   SEE: Long codes starting with  $argon2id$
   SAY: "The database only holds scrambled fingerprints (Argon2id hashes),
         never the passwords themselves."

--- V3. Stored files are locked (encrypted) ---
1. SCRIPT WINDOW: type
        .venv\Scripts\python -c "print(open('demo_files/hr_appraisals.pdf','rb').read(40))"
   SEE: Starts with  %PDF  (a readable PDF).
2. Then type
        .venv\Scripts\python -c "import glob,os;f=max(glob.glob('backend/storage/*.bin'),key=os.path.getmtime);print(f);print(open(f,'rb').read(40))"
   SEE: Random-looking bytes. No %PDF anywhere.
   SAY: "On disk, every file is locked with AES-256 encryption. Stealing the
         disk gives you nothing readable."

--- V4. Messages are stored locked too ---
1. SCRIPT WINDOW: type
        .venv\Scripts\python -c "import sqlite3;[print(s,'->',r,':',c[:24].hex()) for s,r,c in sqlite3.connect('backend/data/securelink.db').execute('select sender_id,recipient_id,ciphertext from messages')]"
   SEE: Sender -> receiver, then random hex instead of the text.
   SAY: "Even someone reading the database can't read the chats."

--- V5. The login cookie is protected ---
1. Edge (Anna): press F12 > [Application] tab > Cookies > https://localhost:8443
   SEE: The cookie "sl_session" with HttpOnly ✓, Secure ✓, SameSite Strict.
2. Click the [Console] tab, type   document.cookie   and press Enter.
   SEE: ""  (empty)
   SAY: "Scripts on the page can't steal the login cookie, and it's only
         sent over HTTPS to our own site."
   Press F12 to close.

--- V6. Network analysis pipeline (with SAMPLE traffic) ---
We can't record real traffic yet (Npcap isn't installed), so we use a
generated sample recording that looks like real traffic: a login, a message
and an attacker.
1. SCRIPT WINDOW: type
        .venv\Scripts\python scripts\make_sample_pcap.py
   SEE: "wrote sample_capture.pcap: 4594 packets of SAMPLE traffic"
2. Then type
        .venv\Scripts\python analysis\pcap_to_sqlite.py sample_capture.pcap --label sample --mode http --port 8080 --server-ip 192.168.1.10
   SEE: "Imported capture ... plaintext_exposures=8" and 6 security events:
        failed connections, too many requests, wrong protocol, port scan,
        traffic burst, repeated failed logins.
   SAY: "Our tool reads a network recording with PyShark, saves every packet
         into a database, and spots attack patterns automatically."
3. Chrome (admin): [Dashboard] > scroll to "Network" and "Security alerts".
   SEE: The packet counts and the 6 alerts.
4. (Optional) Show the saved packets:
        .venv\Scripts\python -c "import sqlite3;[print(r) for r in sqlite3.connect('backend/data/securelink.db').execute('select source_ip,destination_ip,protocol,destination_port,packet_size,flags,risk_score from network_packets limit 8')]"

--- V7. Security measurements ---
1. SCRIPT WINDOW: type
        .venv\Scripts\python evaluation\image_metrics.py demo_files\team_photo.jpg --save-dir evaluation\results
   SEE: A list of numbers.
   SAY (keep it simple):
     - "Entropy close to 8 for the encrypted photo: it looks completely random."
     - "Correlation close to 0: no pattern from the photo survives."
     - "MSE 0 and PSNR infinite: after unlocking, the photo is exactly the original."
2. Open the folder  evaluation\results  and show  team_photo_cipher.png
   SEE: Pure noise.
3. SCRIPT WINDOW: type
        .venv\Scripts\python evaluation\benchmark.py --server https://127.0.0.1:8443 --ca certs\ca.crt --user dev_dan --password "Demo#2026pass" --recipient hr_anna --sizes 10,100,1024,10240 --reps 2
   SEE: For each file size: time to fingerprint, encrypt, decrypt, upload
        and download, plus speed in MB/s. Takes about 30 seconds.
   SAY: "We measure how much the security costs. It's milliseconds."

PART 3 - NOT SHOWN YET (still to do)
=====================================================================

The code for all of these is finished. What's missing is the setup or
equipment to show them for real.

1. Real network recording with Wireshark.
   Needs: Npcap installed (https://npcap.com) and a restart.
   Will show: Bob's password readable when encryption is off, and only
   scrambled data when it's on (the before/after comparison).

2. Analysing REAL intranet traffic with PyShark.
   Today we only used a generated sample recording (V6).
   Needs: item 1.

3. Catching a real attack from another device on the network.
   Needs: a second laptop on the same Wi-Fi to run attack_sim.py,
   while Wireshark records.

4. Using the app on real phones (Android and iPhone).
   Today we only used the browser's phone view (S3).
   Needs: phone on the same Wi-Fi, the certificate (certs\ca.crt) installed
   on the phone, and a firewall rule for port 8443.
   Then test: login, chat, upload, download, photo preview, auto logout,
   log out, access blocked.

5. Blocking a real outside device.
   Today we faked "outside" by changing a setting (S10).
   Needs: a device that is really on a different network.

6. Full speed test from 10 KB up to 100 MB, and the network overhead
   measured from a real recording.
   Today we ran up to 10 MB on this laptop only (V7).
   Needs: item 1, and about 10 minutes to run.

7. (Optional) Looking inside our own encrypted traffic using a browser
   key log file, for deeper analysis.
   Needs: item 1.

8. Final report with screenshots of all of the above.

Things we will explain honestly in the report:
  - Files are locked with a server key, so the server itself could read
    them. This is not "end-to-end" encryption like WhatsApp.
  - NPCR / UACI are numbers designed for special image ciphers. For our
    standard AES encryption they are reported but don't prove much.
  - With HTTPS on, failed logins can't be seen in the network recording
    (that's the point of encryption), so they are tracked in the audit log.
